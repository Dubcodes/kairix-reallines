## Application-hang correction

`RuntimeProfiler._gc_callback()` previously called the ordinary `observe()` method and then acquired the profiler's non-reentrant `threading.Lock` again. A GC callback may run synchronously while code already owns that lock, creating a credible self-deadlock. The callback now writes only scalar counters and a preallocated fixed-size pause ring while CPython holds the GIL. It never takes the general profiler lock or calls allocation-heavy profiler paths. A bounded-time regression invokes both GC phases while the lock is deliberately owned and fails if the callback does not return within 500 ms.

This removes the identified concurrency hazard; it does **not** prove that it caused the physical field hang. The source manager already releases its ownership lock before worker start/stop/snapshot calls. Pico/GPIO/rotary locks protect local state and do not invoke profiler callbacks. The debug recorder uses separate queue/file locks and performs file I/O outside the queue lock. Stability recording has bounded in-memory rings and no external callbacks while locked.

An independent `EventLoopWatchdog` thread receives a 250 ms async heartbeat. After five seconds without a heartbeat it writes all Python thread stacks through `faulthandler`, labels the process as alive with a stalled loop, and rate-limits automatic dumps to 30 seconds. The diagnostic file is bounded by in-place truncation, preserving the descriptor registered for manual `SIGUSR2` dumps. It never reboots or restarts a service. Watchdog status is included in `/api/performance`.

Engineering runtime, browser-HDMI and native-HDMI polls are single-flight in the browser. Backend HDMI/native status work runs in dedicated bounded executors; concurrent native status callers share one task.

## Native graphics architecture

The prototype is an independent C++17 application under `native/`:

`Pico → existing 200 Hz tracking calculation → mmap pose ring → SDL2 KMSDRM renderer → HDMI`

The browser remains responsible for configuration, calibration, scene editing and diagnostics. The current native milestone renders an internal benchmark or a simple projected world line/marker only. Text, PNGs, groups, complete scene synchronization and production asset handling are intentionally deferred and are not silently represented as supported.

SDL2 with KMSDRM is the first candidate because it supplies a small direct DRM display path, accelerated renderer selection and vsynced presentation without Chromium, Cage or a desktop. The executable sets `SDL_VIDEODRIVER=KMSDRM`, requires an accelerated vsynced renderer and refuses to start unless SDL reports exact `1920×1080@50`. No 60 Hz fallback exists. If physical testing shows that SDL cannot expose adequate timing or stable acceleration on this Pi image, direct DRM/GBM/EGL is the documented next evaluation—not an assumed requirement.

## IPC consistency and failure handling

The fixed protocol is specified in [NATIVE_POSE_PROTOCOL_V1.md](NATIVE_POSE_PROTOCOL_V1.md). It contains pose/producer sequences, Pi acquisition/UART/publication timestamps, Pico sequence/time, coherent XYZ/Pan/Tilt/Roll/FOV, validity flags, and model/reference generations. A 64-slot ring gives approximately 320 ms at 200 Hz and cannot accumulate backlog.

Readers verify protocol, size, two commit generations, active generation and CRC. Producer restart, stale data, invalid tracking, invalid world calibration, model/reference generation changes and corrupt/torn snapshots are observable. Default output policy blanks live graphics; explicit `--stale-policy hold` is diagnostic-only. The renderer never references encoders or changes calibration.

Browser full-state and compact-pose messages now carry the same monotonic acquisition pose sequence. A late full state still applies configuration, but cannot replace newer camera/tracking fields. Older compact poses are discarded.

## Benchmark modes and timing

Stage 1 uses `--mode internal` with `stationary`, `horizontal`, `vertical`, `sine` or `reversal`. Motion is a function of monotonic elapsed time, not frame count.

Stage 2 modes are:

- `--mode latest`: newest coherent pose immediately before drawing.
- `--mode interpolate --interpolation-delay-ms 10`: bounded ring history sampled at an explicit delayed display timestamp. No extrapolation is performed.

`SIGUSR1` exports bounded diagnostics. The report separates render duration, `SDL_RenderPresent` call duration, observed frame interval, missed intervals, repeated pose frames, pose/acquisition/UART age, producer/reference/model changes and invalid/stale snapshots. SDL2 does not expose a guaranteed physical page-flip completion timestamp through this path; the report says so and does not call present-call return time scanout latency.

No native frame-pacing, latency, CPU, GPU or memory measurement has yet been collected on a Pi. Automated tests validate deterministic motion, interpolation, exact mode rejection, projection fixtures, IPC integrity and bounded histories. Actual measurements must populate the final comparison matrix during physical acceptance.

The existing measured browser/Pi figures from the V1.5 brief remain the comparison baseline; they were not rerun or reclassified. No claim is made that native output is smoother, faster or lower latency until the same physical stimulus and capture path are used for both renderers.

## Projection equivalence

`tests/fixtures/native_projection.csv` is consumed by both browser JavaScript tests and the C++ native-core test. It covers the accepted +X right/+Y forward/+Z up convention, horizontal FOV, Pan/Tilt signs, Roll and optical-centre position. Native results must remain within `1e-6` pixels of `render.js` fixtures. Dot Calibration and camera calibration mathematics were not changed.

## Services and ownership

`kairix-reallines-native.service` is separate from the primary server and the browser HDMI unit. Both HDMI units declare a conflict, so only one may own DRM. Starting native output is always an explicit operator/systemd action; the installer leaves it disabled and stopped and does not stop browser HDMI. The service uses the existing seatd/render permissions, bounded restart limits, `NoNewPrivileges`, a protected filesystem and a private runtime directory.

Engineering exposes start, stop, restart, boot enable/disable, failure reset and measured native status. Native timing is not presented as physical scanout evidence.

## Controlled Pi build and installation

First confirm explicit authorization for package installation and a maintenance window. Then:

```bash
ssh reallines@192.168.0.41
cd /home/reallines/kairix-reallines
git status --short
git fetch origin
git switch wip/live-tuning-dot-lock
git pull --ff-only origin wip/live-tuning-dot-lock
git rev-parse HEAD
.venv/bin/python -m pytest tests -q
```

Only with separate package authorization:

```bash
sudo apt-get update
sudo apt-get install --no-install-recommends build-essential cmake libsdl2-dev
cmake -S native -B native/build -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=ON
cmake --build native/build --parallel
ctest --test-dir native/build --output-on-failure
sudo ./installer/install-native-renderer.sh
systemctl is-enabled kairix-reallines-native.service || true
systemctl is-active kairix-reallines-native.service || true
```

The expected result is disabled/inactive. Start with the self-contained benchmark, explicitly stopping browser HDMI first:

```bash
sudo systemctl stop kairix-reallines-hdmi.service
sudo systemctl start kairix-reallines-native.service
systemctl status kairix-reallines-native.service --no-pager
journalctl -u kairix-reallines-native.service -n 200 --no-pager
sudo kill -USR1 "$(systemctl show -p MainPID --value kairix-reallines-native.service)"
cat /run/kairix-native/renderer-diagnostics.json
```

For live latest-pose comparison, stop native output, edit `/etc/default/kairix-reallines-native` to:

```text
KAIRIX_NATIVE_OPTIONS=--mode latest --pose-file /dev/shm/kairix-reallines-pose-v1 --diagnostics /run/kairix-native/renderer-diagnostics.json
```

Then start it explicitly. For interpolation replace `latest` with `interpolate --interpolation-delay-ms 10`. Do not enable either HDMI implementation at boot until physical acceptance is complete.

## Rollback

```bash
sudo systemctl disable --now kairix-reallines-native.service
sudo rm -f /etc/systemd/system/kairix-reallines-native.service
sudo rm -f /etc/sudoers.d/kairix-reallines-native
sudo rm -f /usr/local/sbin/kairix-native-helper
sudo rm -f /usr/local/bin/kairix-native-renderer
sudo rm -f /etc/default/kairix-reallines-native
sudo systemctl daemon-reload
sudo systemctl reset-failed
sudo systemctl start kairix-reallines-hdmi.service
```

Software rollback does not delete profiles, layouts, references or calibration data.

8. Compare native and Chromium on the same connector/configuration, never concurrently.
9. Confirm Engineering, Calibration, Editor and browser GFX remain fully functional.
10. Keep native autostart disabled until the operator accepts motion quality and recovery.
