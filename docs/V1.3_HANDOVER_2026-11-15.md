## Deployment and rollback

1. Back up the Pi checkout/data and record the current commit/service status.
2. Fetch this branch into a separate checkout; install `requirements.txt` in its virtual environment.
3. Run the full Python, Node and browser matrix with an isolated `KAIRIX_DATA_DIR`.
4. Review/install TLS, credential and the optional root-owned helper using the README commands. Do not expose credential entry over HTTP.
5. Stop the development service, switch the reviewed checkout, start the service and inspect logs. Re-reference Pan/Tilt/Zoom after restart.
6. Roll back by stopping the service, restoring the previous commit/checkout and data backup, then starting and re-referencing. Remove optional helper/sudoers/admin files with the documented removal procedure if abandoning power controls.

- Confirm cumulative counts remain correct when transport snapshots are deliberately skipped and that Pico restart invalidates all references.
- Repeat known-angle Pan/Tilt calibration via Pico and verify mapping changes preserve counts/references.
- Review, edit, cancel, save and delete manual observations while moving the simulator/physical camera; verify historical gold markers never leak into live GFX measurements.
- Open Chrome GFX/Preview and compare browser metrics with OBS, HDMI capture and alternate output. Treat browser metrics as cadence evidence, not genlock proof.
- Check marker/line distances against surveyed values and group visibility in both Control and clean GFX.
- On an isolated Pi maintenance window, test HTTPS auth/backoff, app restart, reboot and shutdown. Confirm acknowledgements, disconnect state and post-restart reference loss. Ensure physical power-on is available before shutdown testing.
