## Deployment and rollback

After the branch has been reviewed and explicitly pushed, deploy in a maintenance window:

1. On the Pi, record `git rev-parse HEAD`, `git status --short` and `systemctl status kairix-reallines-dev.service`; back up `/home/reallines/kairix-reallines/data` outside the checkout.
2. Fetch the reviewed branch, verify its final SHA, stop `kairix-reallines-dev.service`, and check out that exact SHA in `/home/reallines/kairix-reallines` without discarding local changes.
3. Run `.venv/bin/python -m pip install -r requirements.txt`, then the Python/Node validation matrix with a temporary `KAIRIX_DATA_DIR`.
4. Start the service, inspect `journalctl -u kairix-reallines-dev.service`, open Engineering/Calibration/Preview/GFX, and re-reference Pan/Tilt/Zoom. Do not reuse pre-restart session references.
5. Power controls remain disabled unless the administrator separately configures direct HTTPS, interactively runs `sudo .venv/bin/python -m app.power_control provision`, installs the two root-owned templates with the exact README commands, and validates the sudoers file with `visudo -cf`.
6. Roll back by stopping the service, checking out the recorded prior SHA, restoring the data backup if migration files must also be reverted, reinstalling that revision's requirements, starting the service and re-referencing. The README gives the explicit optional power-helper removal command.

### CI dependency repair

The first pushed V1.3 run (`43631502674`) exposed a test-environment dependency omission on Ubuntu/Python 3.13. `fastapi==0.141.1` resolves Starlette 1.10, whose TestClient now imports the distinct `httpx2` package; installing runtime requirements alone therefore failed while collecting `tests/test_power_control.py`. Runtime dependencies remain unchanged. `requirements-test.txt` now layers pinned `httpx2==2.0.0` and `pytest==8.4.2` over `requirements.txt`, `requirements-dev.txt` layers Playwright over the test set, and the four-job CI matrix installs the test set. Standard matrix jobs intentionally leave the six Playwright cases skipped; they remain exercised locally after installing `requirements-dev.txt` and Chromium. A dedicated browser job remains a future CI improvement. The repair is not fully verified until the focused commit is pushed and all four matrix jobs pass.

Validation in a clean disposable environment using the new test requirements passed 249 unittest cases (six Playwright skips) and 243 pytest cases (the same six skips); all seven power-control tests passed against the pinned CI FastAPI/Starlette/httpx2 set. The development environment with Playwright and Chromium passed all 249 cases in both runners, including all six browser cases. Node editor math, 17 frontend contracts, Python compilation, all JavaScript syntax checks and `git diff --check` also passed. Windows/Python 3.12 was available locally; Python 3.10/3.13 and Ubuntu remain covered only by the pending GitHub Actions rerun.
